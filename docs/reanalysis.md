# 图片分析与历史

每次分析以一份图片资产为单位；多帧表示该资产的不同状态，用于辅助识别，统一生成一份描述和一组标签。一个资产可包含多个主体。分析成功后直接更新描述和 AI 标签，保留人工、系统标签；失败或返回空内容时保留当前结果。主动重分析读取最新提示词，普通补全可复用已有结果重建搜索向量。

“系统设置 → 视觉模型”的“GIF 转静态图”开启时，默认按帧序号等分提取首、中、尾三帧，在同一次模型请求中综合分析动作、表情和文字变化。取帧数量可设为 1–3 帧：1 帧为首帧，2 帧为首尾；原 GIF 不变，帧数不足时仅发送实际帧数。多帧请求自动附带同一动画、按时间顺序综合描述和不跨帧累计主体数量的说明，最终仍按分类格式输出一份结果。每帧独立应用图片压缩阈值，多帧可能增加模型用量；主体自动匹配仍使用首帧。关闭后队列跳过 GIF 分析。

## 历史操作

每张图片最多保留三份替换前的备份，当前内容不占额度。图片详情及已完成任务可打开历史。

| 操作 | 行为 |
| --- | --- |
| 回退 | 确认后恢复描述、普通标签和主体核实结果；先备份当前内容并重建搜索向量，分类与主体关联保持不变 |
| 删除 | 确认后永久删除指定备份，不改变当前内容或其他备份 |

仅图片所有者和管理员可管理历史。备份已清理或当前内容变化时需刷新后重试。写入、备份及三份上限清理在同一事务完成；分析期间主体资料变化会重新排队，过期向量不会写回。

## 提示词

- 全局规则在“系统设置 → 视觉模型”管理，具体描述结构由“标签管理 → 分类分析提示词”决定。主体资料补充身份和可见特征，动作、服饰和场景以本图为准。
- 用户自定义内容（包括主动清空）优先；默认提示词更新不会覆盖已保存内容，可重置为默认提示词并保存后应用新版规则。自定义分类默认留空。
- 默认表情包格式：`主体: xxx。文字: xxx。心情/氛围: xxx。表述含义: xxx。`
- 图片详情可填写本次补充要求（最多6000字），不修改全局规则或主体定义。相同图片、相同补充的待处理任务合并，不同补充分别排队。

API 的 `analysis_instructions` 字段适用于分析队列、URL 分析、上传表单及 MCP `add_image`；非空补充强制调用视觉模型，显式跳过分析的上传除外。任务保留输入文本与原始响应，仅管理员可读取完整任务内容。普通用户仅能查看自己图片的分析、向量重建和存储同步任务状态；列表总数同样按归属过滤，其他类型、已删除图片及无法确认归属的旧任务仅管理员可见。普通用户的响应不包含完整输入、原始模型响应、存储参数或内部错误；分析历史仅返回主体名称和并发校验所需的版本信息。日志不记录密钥或图片 Base64。
