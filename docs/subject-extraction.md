# 主体管理、提炼与历史

## 使用流程

1. 管理员在“主体管理”创建或编辑主体；主体关联已有主名称标签，别名也使用普通标签。创建时关联带主名称标签的图片，保留原有其他主体。
2. 点击“提炼”，手选包含主名称标签的参考图。每次最多3张，第一张在成功提交后成为封面；上限可在系统设置中调整为1–3张。补充规则、背景资料和请求预览在“更多设置”中。
3. 点击“提炼并更新”提交后台任务。成功后直接更新主体描述、保留识别备注，失败保留原内容。同一主体同时只允许一个提炼任务；失败后重新选择参考图提交。
4. 需要更新已有图片时，点击“更新描述 · N 张”。范围为当前关联图片，确认数量后入队，分析成功直接生效。

提炼描述只保留身份和识别特征，通常1–3句话；来源、参考图编号和待确认事项放在任务结果中。样本用于本次分析，不训练识别器。

## 历史与权限

每个主体保留最近三份替换前的描述和识别备注，当前资料不占额度。“历史”中可回退或删除指定备份，两种操作均需确认。回退前先备份当前内容；删除不影响当前资料。

主体词典、提炼、关联与历史管理仅管理员可操作。普通用户通过图片标签查看关联名称。回退有版本校验，提炼期间身份信息变化则拒绝应用旧结果；回退主体资料不会自动改写已有图片。

## 分析如何使用主体

- 人工关联或人工标签唯一命中的主体作为可信身份；AI 标签、歧义标签及自动匹配结果仅作候选，结合图片核实。
- 同一主体的名称和别名归并为一份资料；不同主体按位置区分，同一主体可出现多次。
- 外观、服装、动作、数量和场景以当前图片为准，不把定义中不可见的设定写成事实。明显冲突提示检查，不自动修改人工关联。

## 数据与职责

| 模块 | 职责 |
| --- | --- |
| `subjects` | 规范名称、主名称标签、别名标签、描述、识别备注及封面 |
| `image_subjects` | 当前或历史关联、主主体、来源与标签归属 |
| `subject_samples` | 参考图片及标注；当前不写识别向量 |
| `subject_context_service` | 合并人工关联与标签候选，按主体去重 |
| `subject_assignment_service` | 设置关联、同步标签，保护人工结果 |
| `subject_extraction_service` | 多图提炼、直接更新、历史备份与回退 |

标签改名同步规范名称，引用中的分类、主名称及别名标签不能直接删除。切换主体只移除该流程新增且有归属记录的标签，不删除已有人工标签。

## 自动匹配

默认 `subject_matcher_backend=stub`，始终无命中；未接入真实识别器。人工确认优先，自动结果不能覆盖人工或审批确认的身份。

主要配置为 `subject_memory_enabled`、`subject_auto_apply_high_conf`、`subject_high_threshold`、`subject_low_threshold` 和 `subject_max_candidates`；默认值以 `core/config_defaults.py` 为准。

接入真实识别器时，应明确模型与向量维度、按模型隔离样本检索，并通过误报验证调整阈值。自动命中不直接回流为训练样本，避免错误自我强化。

提示词与图片历史见[图片分析](reanalysis.md)，升级步骤见[数据库管理](database.md)。
